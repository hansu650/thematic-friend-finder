# C｜第一周任务：注册与个人资料调研

你是 **C**，本组拟定角色为 **Developer＋数据模型与技术文档**。本周先调研参考产品，提出下一周开发建议。

## 你要做什么

选择 **2 个相关网站或 App**，重点比较：

1. 注册与登录需要什么信息，哪些必填、哪些选填？
2. 昵称、年龄、介绍、兴趣等资料怎样编辑和保存？
3. 信息缺失、输入错误或保存失败时，产品怎样提示？

可以查看实际页面、官方产品截图和官方帮助。记录链接及查看日期；未实际操作的内容注明来源，不写成亲自测试过。无需付费或联系陌生人。

你的特色工作：整理一张字段建议表，写清字段名称、是否必填、校验规则和用途；区分参考产品的实际做法与给我们项目的建议。

## 要交什么

提交一份 Markdown 调研，约 **500–800 字**，包含：

- 两个参考产品的名称、官方链接、查看日期和观察方式。
- 至少两个页面或流程证据；可用真实截图，或带定位说明的官方页面链接。
- 两点值得借鉴、一点不建议采用的做法，分别说明原因。
- 上面的特色工作成果。
- 一条候选用户故事和至少两条可检查的验收条件。
- 一个希望团队一起讨论的问题。

用户故事可从这个方向修改：作为新用户，我希望注册并编辑资料，以便别人了解我的兴趣和交友意向。  
验收条件写成“在什么情况下，做什么操作，应出现什么结果”，不要只写“功能正常”。

## 怎么提交

1. 接受组长的仓库协作者邀请；如果打不开私有仓库，把自己的 GitHub 用户名发给 A，由 A 添加。
2. 从最新的 `main` 创建自己的 `w1/c-research` 分支。可在 GitHub 网页的分支下拉框创建。
3. 在该分支按上面的路径新增调研 MD，并上传需要的截图；只提交本人的材料。
4. 提交更改后，通过 **Compare & pull request** 发起 PR：base 为 `main`，compare 为自己的分支。
5. PR 描述写清做了什么、文件路径、待讨论问题；根据复核意见，在同一分支继续修改。
