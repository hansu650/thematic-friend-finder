# 周任务与任务卡模板

复制相关部分使用，先填写目标、负责人、验收和真实容量，再由组长发布。示例占位符不代表已经分配或完成。

## 每周任务发布模板

```markdown
# W__ 任务发布：<本周主题>

发布人：A（组长）
周期：YYYY-MM-DD 至 YYYY-MM-DD
所属阶段：准备周 / Sprint 1 / Sprint 2
版本及状态：草案 / 已讨论确认；最后更新日期：____

## 本周目标

<本周要达成的具体结果，以及与 Sprint Goal 的关系>

## 五人分工

| 卡片 | 负责人 | 任务与特色职责 | 交付物与验收 | 复核人 | 内部期限 |
|---|---|---|---|---|---|
| W__-01 | A |  |  | B |  |
| W__-02 | B |  |  | C |  |
| W__-03 | C |  |  | D |  |
| W__-04 | D |  |  | E |  |
| W__-05 | E |  |  | A |  |

## 容量、依赖与同步

- 五人的本周可用时间：____
- 前置条件、共享文件或接口约定：____
- 日常同步方式与时段：____
- 本周会议、记录员及议题：____
- 谁处理阻塞、何时再次检查：____

## 完成检查与调整

- [ ] 交付物有链接，实际结果与验收一致。
- [ ] 完成自查、他人复核和相应验证。
- [ ] 每人更新真实贡献与 PDP。

调整记录：日期 / 原任务 / 新安排 / 原因 / 参与决定的人。
```

## 单张 Trello 卡片模板

下面部分可直接复制到卡片描述，标题放在 Trello 标题栏。不要直接把完整周任务表粘成一张卡。

```markdown
目标：<为谁解决什么问题>
卡片 ID：W__-__；关联故事：US__
周期：W1 / S1 / S2
负责人：____；复核人：____
内部截止：____；估算：____ 小时

现状与依据：
- 当前已经具备：____
- 本次需要改变或验证：____
- 来源、问题或讨论链接：____

交付物：
- <文件、修改、测试或分析结果>

验收清单：
- [ ] 给定 <前提>，当 <操作>，应当 <可观察结果>。
- [ ] <边界或异常条件及预期结果>。
- [ ] 复核人能打开或运行，证据对应本次交付。

依赖及协作：
- 需要谁先完成什么：____
- 涉及的共享文件及合并约定：____

实际结果与证据：
- <文件、提交、测试、截图或来源链接>
- 未完成或已知限制：____

复核：日期 / 复核人 / 检查内容 / 意见 / 修正结果。
阻塞：原因 / 处理人 / 下一次检查时间；无则写无。
```

研究和文档卡可把 Given / When / Then 改成“来源可核对、观察与建议区分、文件可打开”等具体检查。每张卡保留一名主负责人，协作者和复核人另列；不要把一整周的大任务全部塞进一张开发卡。
